# To3mato iOS 앱 기획서

작성일: 2026-10-27
상태: 기획 초안. 화면 구조와 디자인 원칙, 범위, 기술 방향을 제안한다. 화면 문구는 데스크톱 앱의 승인된 문구만 쓰고 새 문구는 "승인 필요 문구" 절에 모아 둔다. 구현 전 "구현 전 확인"에 답을 받는다.

제품 기준은 `product-plan.md`를 따른다. 동기화와 계정은 `supabase-sync-plan.md`의 계약을 그대로 쓴다. 카피 규칙은 `AGENTS.md`를 따른다.

## 1. 목표

- 같은 계정으로 Mac과 iPhone에서 할 일, 프로젝트, 타이머, 집중 기록이 같아진다. iPhone은 두 번째 기기이자 집 밖에서 쓰는 첫 번째 기기다.
- Mac 앱의 손글씨 종이 디자인을 유지한다. iOS 26의 Liquid Glass는 종이 위에 떠 있는 조작 층에만 쓴다. 내용은 종이, 조작은 유리라는 한 가지 규칙으로 두 디자인을 나눈다.
- 계정 없이도 쓸 수 있다. 로그인과 연동은 Mac과 같은 선택 사항이다.
- 집중 중에는 앱을 보지 않아도 된다. 잠금 화면과 Dynamic Island, 알림으로 남은 시간과 체크인을 전달한다.

범위 밖: iPad 전용 레이아웃, Apple Watch, 위젯의 조작 기능, 커뮤니티. iPad는 iPhone 레이아웃을 확대해 실행만 되게 한다.

## 2. Mac 앱과 iPhone의 차이

| 항목 | Mac 앱 | iPhone |
| --- | --- | --- |
| 화면 구조 | 왼쪽 작업 영역 + 오른쪽 실행 영역을 한 화면에 | 작업 영역은 탭으로, 실행 영역은 화면 하단에 항상 떠 있는 타이머 바로 |
| 입력 | 마우스와 키보드. 드래그로 순서 변경 | 터치. 길게 눌러 순서 변경, 스와이프로 날짜 이동·완료 |
| 타이머 알림 | 트레이 제목과 시스템 알림 | Live Activity(잠금 화면·Dynamic Island)와 알림 |
| 3초 클립 | 웹캠 촬영, 기기 안 합성 | 전면 카메라 촬영, 기기 안 합성. 같은 720×960 세로 프레임 |
| 저장 | SQLite(`node:sqlite`) | SQLite(GRDB) 또는 SwiftData. 같은 테이블과 ID 규칙 |
| 로그인 | 이메일 로그인 링크를 Mac에서 열기 | 이메일 로그인 링크를 iPhone에서 열기(Universal Link) |
| 백그라운드 | 메인 프로세스가 250ms 티커로 타이머 진행 | 앱이 중지되어도 시작 시각 기준으로 계산. 종료 시각에 알림 예약 |

데스크톱의 "왼쪽 탭을 전환해도 실행 영역은 유지된다"는 원칙을 iPhone에서는 "어느 탭에서도 하단 타이머 바가 유지된다"로 옮긴다.

## 3. 디자인 원칙: 종이와 유리

### 3.1 역할 분리

| 층 | 역할 | 재질 | 예 |
| --- | --- | --- | --- |
| 바탕 | 공간 | 점무늬 종이 `--bg` + `--bg-dots` | 모든 화면 배경 |
| 내용 | 사용자가 쓴 것, 기록된 것 | 종이 `.paper`, 테이프, 손글씨 글꼴, 삐뚤한 모서리 `--wobble-*`, 기울기 `--tilt-*` | 할 일 행, 프로젝트 표지, 티켓, 영수증, 타이머 판 |
| 조작 | 이동과 명령 | Liquid Glass | 탭 바, 하단 타이머 바, 내비게이션 바의 버튼, 시트의 위쪽 조작 줄, 떠 있는 추가 버튼 |

유리는 종이 위에서만 산다. 유리 안에 종이를 넣지 않고 종이 안에 유리를 넣지 않는다. 종이 카드 안의 버튼(`일시정지`, `저장`, `+`, `−`)은 Mac과 같은 손글씨 버튼 스타일(`.btn-primary`, `.circ`, `.seg`)을 유지한다.

### 3.2 유리의 색

- 유리는 시스템 기본 `glassEffect(.regular)`를 쓰고 자체 색을 넣지 않는다. 아래 종이의 복숭아색이 비쳐 자연스럽게 따뜻해진다.
- 주 동작 버튼 하나만 `.tint(--red)`를 쓴다. 하단 타이머 바의 재생·일시정지 버튼이다. Mac의 빨간 `일시정지` 버튼과 같은 자리다.
- 집중 중 타이머 바는 `--peach-panel` 종이 위에 유리를 올린 모습으로, 휴식 중에는 `--green-light` 위에 올린 모습으로 바뀐다. 색은 유리가 아니라 유리 아래의 종이가 바꾼다. 트레이 설계의 "휴식 중에는 같은 도형에 색만 바꾼다" 규칙과 같다.

### 3.3 모양과 글꼴

- 유리 조작부는 시스템 모양(캡슐·둥근 사각형)을 그대로 쓴다. 삐뚤한 `--wobble` 모서리와 기울기는 종이에만 적용한다. 두 재질을 모양으로도 구분하기 위해서다.
- 유리 위 글자는 시스템 글꼴(SF Pro, Apple SD 산돌고딕)을 쓴다. 종이 위 글자는 Mac과 같은 Poor Story와 Gamja Flower를 번들한다. 숫자는 `Poor Story Digits` 규칙을 그대로 적용한다.
- 아이콘은 Mac의 `Icon.svelte` 선 아이콘을 SF Symbols 중 가장 가까운 것으로 바꾼다. 마스코트와 토마토 도장은 SVG 그대로 쓴다.

### 3.4 접근성과 폴백

- `Reduce Transparency`가 켜지면 유리를 `--paper-tab` 색의 불투명 종이로 바꾼다. Mac의 왼쪽 탭 띠 색이다.
- iOS 18 이하에서는 같은 자리를 `.ultraThinMaterial`로 그린다. 레이아웃은 바꾸지 않는다.
- 다크 모드는 1차 범위에서 제외한다. Mac 앱에 다크 모드가 없다. 시스템 설정과 무관하게 종이색을 유지한다.

## 4. 화면 구성

### 4.1 탭

하단 유리 탭 바 네 개. Mac의 세로 내비게이션 순서를 따르되 `설정`은 탭에서 빼고 할 일 화면의 오른쪽 위 버튼으로 옮긴다.

1. 할 일
2. 프로젝트
3. 캘린더
4. 집중 로그

탭 바 위에 하단 타이머 바가 붙는다. 타이머가 없으면 타이머 바는 `집중 대기` 상태로 `오늘 할 일`의 첫 미완료 항목 제목과 재생 버튼만 보인다. Mac 트레이의 "집중 시작은 오늘의 첫 미완료 작업을 시작한다" 규칙과 같다.

### 4.2 하단 타이머 바

높이 두 줄의 유리 바. 왼쪽부터 현재 할 일 제목, 남은 시간 `MM:SS`, 재생·일시정지 버튼, 종료 버튼. 상태 줄은 Mac의 `timerMenuState()` 값(`집중 대기`, `집중 중`, `일시정지`, `휴식 중`, `휴식 대기`)을 그대로 쓴다.

바를 위로 끌거나 누르면 실행 화면이 시트로 올라온다. 시트 내용은 Mac의 오른쪽 실행 영역과 같다.

1. 타이머 판(`--peach-panel` 종이, 테이프, 토마토 성장 3D, 할 일 제목, 큰 시계, 진행 막대, 예상 토마토)
2. 액션 버튼(`일시정지`·`재개`, 종료)
3. 오늘 할 일 목록(각 행에 재생 버튼)

체크인 단계(`checkin`)가 되면 시트가 자동으로 열리고 타이머 판 자리에 Mac의 `진척 확인` 카드가 들어간다. 항목과 버튼은 Mac과 같다: `처음 예상`, `실제 사용`, `남은 예상`, `완료`, `이어서 할 일 만들기`, `저장`, `저장하면 휴식을 시작합니다.`

### 4.3 할 일

Mac의 `TodoView`를 세로 한 열로 옮긴다. 섹션 순서는 `getTodoSections()`와 같다: 오늘, 내일, 할 일이 있는 날짜, 미완료가 있는 지난 날짜, 미지정.

- 오늘 섹션 위에 `오늘 가능` 스테퍼와 토마토 도장 줄(`CapacityRow`)을 둔다.
- 할 일 행은 Mac과 같은 종이 행: 순번 동그라미, 제목, 예상 `1 | 2` 세그먼트, 사용 토마토 `n / m`, 더보기.
- 행을 오른쪽으로 스와이프하면 완료, 왼쪽으로 스와이프하면 `내일로`·`보관`·`삭제`. 길게 누르면 순서 변경.
- 각 섹션 끝의 바로 추가 줄(`.quick`)과 `템플릿`, `할 일 추가` 버튼을 유지한다. `할 일 추가`는 시트로 열리고 Mac의 `하나 추가`, `여러 개 추가`, `템플릿` 모드를 같은 시트에 둔다.
- 계획 시작 카드(`PlanCard`)는 Mac과 같은 조건으로 오늘 섹션 위에 종이 카드로 열린다.
- 오른쪽 위에 날짜 스티커와 설정 버튼.

### 4.4 프로젝트

Mac의 `ProjectsView`와 `DiaryView`를 그대로 옮긴다. 목록은 표지 이미지 종이 카드의 세로 목록이다. 프로젝트 상세는 표지, `결과물`, `티켓`·`남은 할 일`·`실제 사용` 숫자, 진행 막대, 남은 할 일 목록, 다이어리(티켓 목록)다. 표지 이미지는 사진 앱에서 고른다.

### 4.5 캘린더

Mac의 주간 캘린더를 가로 스크롤 요일 띠와 그 아래 선택한 날의 할 일 목록으로 바꾼다. 요일 칸에는 날짜와 배치 토마토 수만 표시한다. 할 일 행을 길게 눌러 다른 요일 칸에 놓으면 `task:move`다.

### 4.6 집중 로그

Mac의 `FocusLog`와 같다. 이번 주 숲 섬 3D, 주 이동, 클립 목록, 영상 편지 재생·저장. 저장은 사진 앱으로 저장한다.

### 4.7 설정

Mac의 설정 카드를 그대로 쓴다: `계정`, `알림`, `포모도로 설정`, `최근 집중 기록`, `로컬 데이터`. `트레이 표시`와 `업데이트` 카드는 iOS에 없으므로 뺀다. `로컬 데이터`의 JSON 가져오기·내보내기는 파일 앱을 쓴다.

### 4.8 돌아보기

Mac의 `ReviewView`와 같은 내용을 전체 화면 시트로 연다. 알림 클릭과 설정의 `돌아보기` 버튼으로 연다.

### 4.9 첫 실행 안내와 로그인

Mac의 4단계 안내(`일단 3번만 해봅시다. 토오오오마토.` 부터 `기록을 확인`까지)와 버튼(`다음`, `이전`, `건너뛰기`, `시작`, `로그인 없이 시작`, `나중에`)을 그대로 쓴다. 로그인 화면은 `이메일` 입력과 `로그인 링크 받기` 버튼이다. 링크를 iPhone에서 열면 Universal Link로 앱이 받아 로그인된다.

## 5. 집중 중 경험

### 5.1 Live Activity

집중과 휴식 동안 Live Activity를 띄운다. 잠금 화면에는 할 일 제목, 남은 시간, 토마토 진행을 보여준다. Dynamic Island의 작은 상태에는 남은 시간만, 펼친 상태에는 제목과 `일시정지`·`종료` 버튼을 둔다. 버튼은 App Intent로 앱의 명령(`timer:pause`, `timer:stop`)을 그대로 보낸다.

Live Activity의 모양은 시스템 기본이다. 종이 질감을 넣지 않는다. 토마토 도장과 빨간색 `--red`만 가져온다.

### 5.2 백그라운드와 알림

- 앱이 중지되어도 타이머는 서버 또는 로컬의 시작 시각 기준으로 흐른다. 복귀 시 다시 계산한다. `supabase-sync-plan.md` 6절과 같다.
- 집중 시작 때 종료 예정 시각에 로컬 알림을 예약한다. 제목은 할 일 제목, 본문은 Mac 알림과 같다. 일시정지·종료·전환 때 알림을 다시 예약하거나 취소한다.
- 집중이 끝나면 체크인 단계로 넘어간다. 알림을 누르면 체크인 카드가 열린다. 체크인 응답 전에는 휴식을 시작하지 않는다.
- 계획·돌아보기 알림은 `planAt`, `reviewAt`, `remindDays` 설정으로 로컬 예약한다. Mac의 `dueReminder()` 규칙과 같고 기기별로 하루 한 번이다.

### 5.3 3초 클립

집중이 끝나고 체크인 저장 뒤 Mac과 같은 토스트(`인증샷을 남길까요?` / `네, 남길게요`)를 띄운다. 전면 카메라로 3초 준비 뒤 3초를 찍고 마이크 없이 저장한다. 프레임과 글자 합성은 Mac의 `video.ts`와 같은 규칙으로 AVFoundation에서 한다. 월요일 영상 편지도 기기 안에서 합성한다. 연동이 켜져 있으면 Mac과 같은 asset 큐로 올리고 받는다.

카메라 권한 설명문은 Mac의 `NSCameraUsageDescription`과 같은 문장을 쓴다.

## 6. 데이터와 동기화

- 로컬 저장은 Mac의 SQLite 스키마(v4 이후)와 같은 테이블, 같은 ID 규칙, 같은 변경 명령 큐를 쓴다. `domain.mjs`의 규칙을 Swift로 옮기되 `tests/*.test.mjs`의 시나리오를 같은 입력·기대값으로 XCTest에 옮겨 두 구현이 같은 결과를 내는지 검증한다.
- 동기화 엔진은 `supabase-sync-plan.md`의 `LocalRepository`, `SyncTransport`, `SessionStore`, `AssetStore`, `Clock`, `NotificationAdapter` 인터페이스를 Swift로 구현한다. 프로토콜 버전은 Mac과 같다.
- 세션 토큰은 Keychain에 둔다. 앱에는 publishable key만 넣는다.
- 공유 타이머는 계정당 하나다. Mac에서 시작한 타이머가 iPhone 하단 바에 바로 나타나고 어느 쪽에서든 조작한다.
- 연동이 꺼진 상태에서는 모든 기능이 기기 안에서 동작한다.

### JS 도메인 재사용 여부

Swift로 다시 쓰는 대신 `domain.mjs`를 JavaScriptCore로 실행하는 방법이 있다. 장점은 규칙을 두 번 쓰지 않는 것이고 단점은 Live Activity와 App Intent가 별도 프로세스라 JS 실행 비용이 생기는 것이다. 권장안은 Swift로 다시 쓰고 시나리오 테스트로 묶는 것이다. 결정 항목으로 둔다.

## 7. 기술 스택

| 기술 | 역할 |
| --- | --- |
| Swift, SwiftUI | 화면 구성. iOS 26 Liquid Glass API(`glassEffect`, `GlassEffectContainer`, 탭 바·툴바 기본 유리) |
| GRDB | SQLite 저장. Mac과 같은 스키마 |
| supabase-swift | Auth, Postgres RPC, Realtime, Storage |
| ActivityKit, App Intents | Live Activity와 Dynamic Island 조작 |
| AVFoundation | 3초 클립 촬영과 합성 |
| RealityKit | 토마토 성장과 숲 섬 3D. `public/models/farm`의 glTF를 USDZ로 변환 |
| Xcode Cloud 또는 GitHub Actions macOS 러너 | 빌드, 테스트, TestFlight 업로드 |

최소 지원 버전은 iOS 18이다. 유리는 iOS 26에서만 켜고 18~25는 3.4절의 폴백을 쓴다.

저장소는 이 저장소 안의 `ios/` 디렉터리에 둔다. 동기화 계약과 디자인 토큰을 한 곳에서 관리하기 위해서다. `src/styles/tokens.css`의 색·글자 크기·간격 값을 Swift 상수로 생성하는 스크립트를 두고 두 플랫폼의 토큰이 어긋나지 않게 한다.

## 8. 구현 순서와 완료 기준

| 단계 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1. 종이 부품과 토큰 | 토큰 생성 스크립트, 종이·테이프·동그라미·토마토·손글씨 글꼴·세그먼트 부품 | Mac 화면과 같은 색·모양의 부품 갤러리 화면 |
| 2. 로컬 할 일과 타이머 | SQLite, 도메인 규칙, 할 일 탭, 하단 타이머 바, 실행 시트, 체크인 | 연동 없이 할 일 추가·배치·집중·체크인·기록 |
| 3. 유리 조작 층 | 탭 바, 타이머 바, 툴바, 시트 조작 줄, 폴백 | iOS 26과 iOS 18에서 같은 레이아웃 |
| 4. 프로젝트·캘린더·설정·돌아보기 | 나머지 탭과 계획 카드, 템플릿, 알림 예약 | Mac과 같은 데이터로 같은 화면 |
| 5. Live Activity | 잠금 화면, Dynamic Island, App Intent 명령 | 앱을 닫고도 남은 시간 확인과 일시정지·종료 |
| 6. 계정과 동기화 | 로그인 링크, Keychain, 명령 큐, Realtime, 공유 타이머 | Mac과 iPhone 사이 `supabase-sync-plan.md` 10절의 핵심 시나리오 통과 |
| 7. 클립과 영상 | 카메라, 합성, 집중 로그, 숲 섬, asset 전송 | Mac에서 찍은 클립이 iPhone 집중 로그에 보이고 그 반대도 같다 |
| 8. 출시 준비 | 개인정보 처리방침·이용약관 링크, 앱 심사 자료, TestFlight | 심사 제출 |

2단계까지는 연동 없이 동작하므로 Supabase 변경 없이 진행한다. 6단계 전에 `supabase-sync-plan.md`의 남은 검증(실제 이메일 로그인, 계정 간 실서버 동기화)을 Mac에서 먼저 끝낸다.

## 9. 승인 필요 문구

기능에 꼭 필요한 최소 문구만 초안으로 둔다. 승인 전에는 넣지 않는다.

| 위치 | 초안 | 비고 |
| --- | --- | --- |
| 할 일 행 스와이프 | `내일로`, `보관`, `삭제`, `완료` | Mac의 계획 카드·돌아보기 버튼과 같은 단어 |
| 집중 로그 영상 저장 | `사진에 저장` | Mac의 `다운로드`를 iOS 동작에 맞춘 명사형 |
| 로컬 알림(집중 종료) | 제목: 할 일 제목. 본문: Mac 알림 본문 그대로 | 새 문장 없음 |
| Live Activity 버튼 | `일시정지`, `재개`, `종료` | Mac 액션 버튼과 같음 |
| 로그인 링크 안내 | Mac 앱에서 승인된 링크 방식 문구 그대로 | 새 문장 없음 |
| 사진 권한 설명 | `프로젝트 표지 이미지를 고르기 위해 사진에 접근합니다.` | 시스템 권한 대화상자에 필요 |
| 알림 권한 설명 | 시스템 기본 대화상자 사용. 별도 문구 없음 | |

탭 이름, 설정 카드 제목, 체크인 항목, 첫 실행 안내, 계정 문구는 모두 Mac의 승인된 문구를 그대로 쓴다.

## 10. 구현 전 확인

1. 설정을 탭에서 빼고 할 일 화면의 버튼으로 옮기는 구성에 동의하는가. 대안은 탭 다섯 개다.
2. 도메인 규칙을 Swift로 다시 쓰는 안과 JavaScriptCore로 `domain.mjs`를 실행하는 안 중 어느 쪽인가.
3. 최소 지원 버전을 iOS 18로 두고 유리는 iOS 26에서만 켜는 것에 동의하는가. 대안은 iOS 26 전용이다.
4. 3D 토마토와 숲 섬을 1차 범위에 넣을지. 뺀다면 타이머 판에는 2D 토마토 도장만 둔다.
5. 3초 클립과 영상 편지를 1차 출시에 넣을지, 2차로 미룰지.
6. iOS 소스를 이 저장소의 `ios/`에 둘지 별도 저장소로 둘지.
7. 로그인 링크의 Universal Link 도메인. `to3mato.doyeong.dev` 하위 경로를 쓰는 것을 권장한다. Supabase의 `additional_redirect_urls`에 추가해야 한다.
8. 9절의 문구 초안.
