# To3mato 마이크로블로그 디자인 명세

작성일: 2026-11-08
상태: 디자인 초안. `microblog-design-brief.md`의 요청에 따라 Claude가 작성했다. 기획 확정 범위는 `microblog-plan.md`와 `MEMORY.md`를 따르며 이 문서의 제안과 가정은 확정 사항이 아니다.

시안: [`design/microblog-preview.html`](design/microblog-preview.html)

## 시안 보는 법

- 저장소의 `docs/design/` 위치에서 브라우저로 연다. 저장소의 `src/styles/tokens.css`, `src/styles/components.css`, 설치된 `@fontsource` 글꼴을 상대 경로로 읽는다. 다른 위치로 복사하면 스타일이 빠진다.
- 네트워크 요청과 클립보드 변경은 없다. 데이터는 시안 안의 예시 값이다.
- 상단 회색 막대와 파란 번호 주석은 검토용이다. 제품 화면에 포함하지 않는다. `검토 주석`을 끄면 제품 화면만 남는다.
- 화면: `공개 프로필`, `공개 범위 설정`, `공유 메뉴`.
- 사용자: `김토마토 씨 (모두 ON)`, `이부끄 씨 (모두 OFF)`. 사용자를 바꾸면 모든 스위치가 해당 상태로 바뀐다. 이후 스위치를 직접 눌러 개별 조합을 확인할 수 있다. 설정 화면의 스위치는 공개 프로필 화면에도 반영된다.
- 너비 1600px 전후의 창에서 보기를 권장한다. 앱 시안은 Mac 앱 데스크톱 배치를 고정으로 보여준다.

## 디자인 방향

공개 프로필은 앱의 손글씨 종이 화면을 그대로 이어 쓴다. 링크를 연 사람이 To3mato 앱의 일부를 본다고 느끼도록 하고 별도의 웹 서비스처럼 보이지 않게 한다.

| 선택 | 근거 |
| --- | --- |
| 점무늬 바탕과 종이 카드 | 앱 `body`의 `--bg` 점무늬와 `.paper`를 그대로 쓴다. 공개 프로필이 앱과 같은 제품으로 보인다. |
| 잔디 색을 토마토 계열로 | GitHub의 초록 대신 `--peach-deep` → `--tomato-half` → `--tomato` → `--red-deep` 단계를 쓴다. 앱에서 완료한 포모도로를 빨간 토마토 도장으로 표시하는 규칙과 맞춘다. |
| 오늘 완료한 포모도로를 큰 숫자 + 도장으로 | 공통 정보 중 매일 바뀌는 값이다. 타이머 판과 같은 `.paper.peach` 면에 두어 앱의 실행 영역과 연결한다. 도장은 앱의 `.tomato.filled`와 같은 모양이다. |
| 완료한 할 일을 티켓으로 | 프로젝트 다이어리의 `Ticket` 부품을 재사용한다. 티켓 메모가 이미 티켓 안에 있는 정보라 같은 형태가 자연스럽다. |
| 영상은 상단 배경 영역에만 | 기획대로 영상은 배경 역할만 한다. 카드 뒤 상단 띠에만 두어 글자 대비를 해치지 않는다. 영상 목록이나 재생 조작 화면은 두지 않는다. |
| 설정은 기존 설정 카드 형식 | `.settings-card`의 제목, 행 간격, 점선 구분을 따른다. 새 부품은 스위치 하나만 추가한다. |

## 1. 공개 프로필

### 구성

위에서 아래 순서다. 데스크톱에서는 왼쪽 열과 오른쪽 열로 나눈다.

| 순서 | 영역 | 공개 조건 | 기존 부품 |
| --- | --- | --- | --- |
| 1 | 상단 배경 영역 | 항상. 주간 영상 ON이면 영상, OFF면 단색 그라데이션 | 없음. 새 영역 |
| 2 | 표시 이름 카드 | 항상 | `.paper`, `.tape` |
| 3 | 오늘 완료한 포모도로 | 항상 | `.paper.peach`, `Tomato` |
| 3-1 | 집중 시간 | 후보 항목 ON | `.paper.peach` 안의 점선 구분 행 |
| 4 | 잔디 | 항상 | `.paper`. 칸은 새 부품 |
| 5 | 프로젝트 | 후보 항목 ON | `.paper.alt`, `.project-dot` |
| 6 | 완료한 할 일 | 후보 항목 ON | `Ticket`, `.chip`, `.datestamp` |
| 6-1 | 티켓 메모 | 후보 항목 ON | `.ticket-note` |

- 열람자 계정, 댓글, 좋아요, 팔로우 버튼은 없다. 영상 목록, 개별 영상 게시물, 지난 영상 보관함도 없다.
- 표시 이름은 첫 공유 때 입력받은 값이다. 3장 `첫 공유`를 따른다.
- 프로필 사진은 원하는 사용자만 넣는다. 사진이 있으면 이름 카드 왼쪽에 원형 사진(모바일 56px, 데스크톱 72px)을 두고, 없으면 이름만 보여준다. 빈 사진 자리를 공개 프로필에 남기지 않는다. 시안에서 김토마토 씨는 사진 있음, 이부끄 씨는 사진 없음이다.
- 페이지 하단 푸터는 두지 않았다. 악용 신고 연락처는 `domain-migration.md`의 기준상 필요하므로 위치와 문구를 `문구` 절에 올린다.

### 두 사용자의 상태

| 사용자 | 보이는 영역 | 시안 표현 |
| --- | --- | --- |
| 김토마토 씨 (모두 ON) | 1~6-1 전체 | 상단 영상 배경 위로 이름 카드가 겹친다. 오른쪽 열에 잔디, 프로젝트, 완료한 할 일 티켓이 이어진다. |
| 이부끄 씨 (모두 OFF) | 1(그라데이션), 2, 3, 4 | 상단 배경이 토마토 계열 단색 그라데이션이다. 이름 카드가 배경에 겹치는 배치는 김토마토 씨와 같다. 오른쪽 열에는 잔디만 있다. |

2026-11-08 사용자 결정: 두 사용자 모두 배경이 있어야 한다. 주간 영상을 공개하지 않으면 단색 그라데이션 배경을 쓴다. 주간 영상 공개가 켜져 있어도 새 영상이 없는 주에는 지난 영상을 유지하지 않고 그라데이션을 보여준다.

모두 OFF여도 화면이 비어 보이지 않도록 공통 정보 카드의 크기를 줄이지 않는다. 오늘 완료한 포모도로가 0이면 숫자 `0`과 빈 토마토 윤곽 하나를 보여주는 표현을 제안한다. 시안에는 0인 상태를 넣지 않았다.

### 잔디

- 열은 주, 행은 요일이다. 왼쪽에 `월`, `수`, `금`, 위쪽에 달 이름을 표시한다. 앱의 `weekBounds`와 같이 월요일을 주의 시작으로 둔다.
- 칸 색은 5단계다. 0은 종이색 칸에 `--line` 윤곽, 이후는 `--peach-deep`, `--tomato-half`, `--tomato`, `--red-deep`이다.
- 오늘 칸은 `--highlight` 테두리로 표시한다. 앱에서 초점과 강조에 쓰는 색이다.
- 칸 모서리는 퍼센트 값의 살짝 삐뚤한 모양이다. 모바일의 작은 칸에서도 원이 되지 않고 손으로 그린 네모로 보인다.
- 오른쪽 아래에 5단계 색 견본만 둔다. 견본 양끝의 글자는 `문구` 절에 있다.
- 각 칸에는 화면 낭독기용 날짜와 수를 붙인다. 칸이 140개라 낭독이 길어지므로 구현 시 기간 합계 한 줄로 대체하는 방식을 함께 검토한다.

### 배경 영상

확정 범위: 원하는 사용자만, 최신 한 주 분량의 주간 영상 하나, 배경으로만, 매주 자동 교체, 주차 선택 UI 없음.

아래는 디자인 제안이다.

| 항목 | 제안 |
| --- | --- |
| 위치 | 페이지 상단 배경 띠. 모바일 240px, 데스크톱 320px 높이. 이름 카드와 오늘 카드가 아래쪽을 덮는다. |
| 재생 | 소리 없이 자동 재생하고 반복한다. `playsinline`을 적용해 인스타그램 인앱 브라우저에서 전체 화면으로 바뀌지 않게 한다. |
| 정지 | 오른쪽 위에 정지·재생 아이콘 버튼을 둔다. 움직이는 콘텐츠를 멈출 수단을 제공하기 위해서다. 아이콘 버튼의 접근성 이름은 `영상 정지`, `영상 재생`이다. |
| 움직임 줄이기 | 기기의 움직임 줄이기 설정이 켜져 있으면 첫 화면에서 정지 상태로 시작하고 영상의 한 장면을 보여준다. 시안의 `움직임 줄이기 흉내`로 확인한다. |
| 글자 대비 | 영상 위에 글자를 직접 올리지 않는다. 띠 아래쪽은 `--bg` 색으로 흐려지게 하고 글자는 종이 카드 위에만 둔다. |
| 대체 배경 | 영상 OFF 상태, 새 영상이 없는 주, 영상을 불러오는 동안, 불러오기 실패 시 모두 같은 단색 그라데이션을 보여준다. 배경 영역의 높이가 같아 레이아웃이 흔들리지 않는다. 그라데이션에는 정지 버튼을 두지 않는다. |
| 그라데이션 색 | 아래 6종 중 하나를 사용자마다 해시로 고른다. 모두 165도, 밝은 왼쪽 위에서 짙은 오른쪽 아래로 가는 단색 계열이다. 아래쪽은 영상과 같이 `--bg`로 흐려진다. 새 색 토큰은 없다. |

2026-11-08 사용자 결정: 그라데이션 색은 사용자를 해시해서 정한다.

#### 그라데이션 6종

| 번호 | 계열 | 토큰 |
| --- | --- | --- |
| g0 | 토마토 | `--peach` → `--peach-deep` → `--tomato-half` → `--coral` |
| g1 | 버터 | `--butter` → `--butter-deep` → `--highlight` |
| g2 | 잎 | `--green-light` → `--tape-green` → `--leaf-light` → `--leaf` |
| g3 | 복숭아 | `--peach-current` → `--peach` → `--peach-deep` → `--coral-light` |
| g4 | 크라프트지 | `--done` → `--kraft` → `--kraft-deep` |
| g5 | 산호 | `--peach` → `--coral-light` → `--coral` → `--tomato-light` |

임의의 색상값을 해시로 만들지 않고 정해진 목록에서 고른다. 모든 결과가 앱의 색 체계 안에 있고 아래쪽 카드와 대비가 유지된다.

#### 해시 입력

현재 To3mato는 사용자 이름을 수집하지 않는다. 동기화 계정에는 이메일 로그인과 계정 ID만 있다. 그래서 이름을 해시 입력으로 쓸 수 없다.

| 후보 | 판단 |
| --- | --- |
| 이메일 | 쓰지 않는다. 개인정보이고 이메일을 바꾸면 색이 바뀐다. |
| 계정 ID (Supabase 사용자 ID) | 가능하지만 내부 식별자를 공개 화면 계산에 엮게 된다. |
| 공개 프로필 ID | 제안. 공유 링크를 만들 때 어차피 생기는 공개용 식별자다. 공개 페이지가 이미 가진 값이라 서버에서 다른 정보를 꺼내지 않고 색을 정할 수 있다. |

- 계산: 공개 프로필 ID 문자열 → FNV-1a 32비트 해시 → 6으로 나눈 나머지. 시안은 이 방식으로 구현했다. 시안 ID `pf_8c2e1a`는 g0, `pf_3b7d90`은 g3이 나온다.
- 확인할 점: 공개를 중지한 뒤 다시 공개하면서 링크를 새로 만들면 ID가 바뀌어 색도 바뀐다. 색을 유지하려면 공개 프로필 ID와 별도로 처음 한 번 정한 색 번호를 저장한다.

시안의 영상은 실제 파일 대신 따뜻한 색 면 4개를 3초마다 바꾸어 3초 영상 묶음을 흉내 낸다.

### 반응형

공개 프로필은 같은 마크업을 쓰고 컨테이너 너비 760px을 기준으로 배치를 바꾼다.

| 너비 | 배치 |
| --- | --- |
| 760px 미만 (모바일) | 한 열. 좌우 여백 16px. 이름 → 오늘 완료한 포모도로 → 잔디 → 프로젝트 → 완료한 할 일 순서. 첫 화면에 이름, 오늘 수, 잔디 일부가 들어온다. |
| 760px 이상 (데스크톱) | 왼쪽 300px 열에 이름과 오늘 카드, 오른쪽 열에 잔디와 선택 공개 항목. 왼쪽 열은 스크롤 시 위에 고정된다. 본문 최대 너비 1080px. |

인스타그램 프로필 링크로 들어오는 모바일 흐름을 기본으로 둔다. 인앱 브라우저 상단 막대가 화면을 차지하므로 첫 화면 안에 공통 정보가 보이도록 이름 카드를 작게 유지한다. 티켓은 모바일에서 꼬리 너비를 78px로 줄이고 도장을 50px로 줄인다.

## 2. 공개 범위 설정

### 위치

집중 로그 탭의 기존 소개 문단(`집중 로그` / `집중 완료 후 촬영한 3초 영상을 주별로 모읍니다.`) 바로 아래, 영상 편지함 위에 설정 카드를 둔다. 기존 문구는 바꾸지 않았다.

- 근거: 주간 영상 공개가 이 탭의 영상과 직접 연결된다. 매주 영상 편지를 확인하러 오는 탭이라 공개 상태를 자주 보게 된다.
- 대안: 영상 편지함 아래 또는 탭 하단 안내 문단 위. 편지함을 우선하려면 대안을 고른다.

### 구성

| 행 | 표시 | 상태 |
| --- | --- | --- |
| 카드 제목 `공유 프로필` | 제목 | 사용자 가칭 |
| 잔디 | 자물쇠 아이콘 | 항상 공개. 끌 수 없음 |
| 오늘 완료한 포모도로 | 자물쇠 아이콘 | 항상 공개. 끌 수 없음 |
| 주간 영상 | 스위치 | 공개 항목으로 확정 |
| 집중 시간 | 스위치 | 검토 중 후보 |
| 프로젝트 | 스위치 | 검토 중 후보 |
| 완료한 할 일 | 스위치 | 검토 중 후보 |
| 티켓 메모 | 스위치. 완료한 할 일 아래로 들여씀 | 검토 중 후보 |

- 항상 공개되는 행과 선택 행 사이에 실선을 넣어 두 묶음을 구분한다. 묶음 이름은 `문구` 절에 있다.
- 후보 항목의 이름, 목록, 순서, 초기값은 미정이다. 시안의 ON/OFF는 두 사용자를 구별하기 위한 값이며 초기값 제안이 아니다.
- 티켓 메모는 완료한 할 일에 딸린 정보로 가정했다. 완료한 할 일이 OFF면 티켓 메모 스위치는 비활성화되고 값은 유지한다. 제안이다.
- 프로젝트가 OFF이고 완료한 할 일이 ON이면 티켓의 프로젝트 칩을 숨긴다. 제안이다.
- 일괄 ON/OFF 기능은 제공 여부가 미정이라 넣지 않았다.
- 프로필 공유 중지는 모두 OFF와 다른 동작이다. 동작이 미정이라 시안에 넣지 않았다. 이 카드 맨 아래의 텍스트 버튼(`.text-button`) 위치를 제안한다.

### 스위치 (새 부품)

| 속성 | 값 |
| --- | --- |
| 크기 | 50 × 28px. 행 높이 최소 48px |
| 꺼짐 | 흰 바탕, `--line-strong` 테두리, `--stroke-soft` 손잡이 |
| 켜짐 | `--tomato` 바탕, `--red` 테두리, 흰 손잡이 오른쪽 |
| 모양 | 테두리 반경을 조금씩 다르게 준 알약, 손잡이는 `--blob` |
| 비활성 | 불투명도 0.4. 기존 `button:disabled`와 같은 방식 |
| 초점 | 기존 `--highlight` 3px 윤곽 |
| 의미 | `role="switch"`, `aria-checked`, 행 이름과 연결 |
| 움직임 | 손잡이 0.18초 이동. 움직임 줄이기 설정에서 끈다 |

ON 색을 `--green` 대신 `--tomato`로 정한 근거: 공개되는 항목이 공개 프로필에서 토마토 계열로 보이는 잔디·도장과 같은 색이 된다. 앱의 주요 동작 색과도 같다.

## 3. 공유 메뉴

### 위치와 흐름

1. 작업 영역 상단의 날짜 표시 왼쪽에 `공유하기` 버튼을 둔다. 형태는 기존 `.btn-line`에 공유 아이콘을 더한 것이다. 작업 영역 상단은 탭을 바꿔도 유지되는 자리라 모든 탭에서 같은 위치에 있다.
2. 누르면 버튼 아래 오른쪽 정렬로 종이 메뉴가 열린다. 항목은 `프로필 공유하기` 하나이며 링크 아이콘을 붙인다.
3. 항목을 누르면 메뉴가 닫히고 링크가 복사된다. 초점은 `공유하기` 버튼으로 돌아간다.
4. 화면 아래에 기존 알림(`.toast`)으로 복사 결과를 2.6초 동안 보여준다.

### 첫 공유

2026-11-08 사용자 결정

- 현재 이름을 수집하지 않으므로 첫 공유 때 표시 이름을 입력받는다.
- 표시 이름은 최대 20자이고 다른 사용자와 같은 이름을 허용한다.
- 프로필 사진은 원하는 사용자만 넣는다.
- 첫 공유 때 공개 범위와 미리보기를 확인한다.
- 첫 공유를 취소하면 대화상자에서 바꾼 공개 범위를 되돌린다.
- 사진 처리 방식은 Claude가 정한다. 아래 `사진` 절이 그 결정이다.

#### 흐름

1. 첫 공유 전 상태에서 `프로필 공유하기`를 누르면 메뉴가 닫히고 첫 공유 대화상자가 열린다.
2. 대화상자에서 표시 이름, 사진, 공개 범위를 정하고 미리보기로 결과를 확인한다.
3. `저장`을 누르면 세 가지를 저장하고 링크를 복사한 뒤 복사 결과 알림을 보여준다. 이후 공유부터는 대화상자 없이 바로 복사한다.
4. 빈 이름으로 저장하면 기존 오류 형식(`할 일 이름을 입력하세요.`)에 맞춰 `표시 이름을 입력하세요.`를 보여주고 입력 칸에 초점을 둔다. 다른 항목은 필수가 아니다.
5. 닫기 버튼과 `Esc`는 공유하지 않고 닫는다. 이름과 사진은 저장하지 않고 공개 범위는 대화상자를 열기 전 값으로 되돌린다. 초점은 `공유하기` 버튼으로 돌아간다.

#### 대화상자 구성

기존 할 일 추가 대화상자(`dialog`, `.dialog-heading`, `.dialog-footer`, `.primary`)의 형식을 따르고 너비만 880px로 넓힌다. 제목은 사용자가 정한 `프로필 공유하기`를 그대로 쓴다.

| 위치 | 항목 | 표현 |
| --- | --- | --- |
| 왼쪽 | 표시 이름 | 입력 칸과 아래 오른쪽의 글자 수(`0 / 20`) |
| 왼쪽 | 사진 | 없으면 점선 빈 원과 `사진 추가`, 있으면 원형 사진과 `사진 삭제`. 버튼은 `.btn-line` |

- 공개 범위 항목의 초기값은 아직 미정이다. 첫 공유 대화상자는 그 초기값을 그대로 보여준다.

#### 이후 변경

`공유 프로필` 카드 맨 위에 `표시 이름` 행을 둔다. 사진이 있으면 작은 원형 사진, 이름, `수정` 텍스트 버튼을 보여준다. `수정`을 누르면 이름과 사진만 있는 기본 너비 대화상자를 `표시 이름 수정` 제목으로 연다. 수정에서는 링크를 복사하지 않는다. 첫 공유 전에는 값 자리에 `없음`을 두고 `수정`을 숨긴다. 이 행의 위치와 동작은 제안이다.

- 메뉴는 `Esc`로 닫는다. 버튼에 `aria-haspopup`, `aria-expanded`를 둔다.
- 메뉴에 항목이 하나지만 사용자가 정한 두 단계(`공유하기` → `프로필 공유하기`)를 유지한다. 이후 다른 공유 항목이 생길 자리다.
- 프로필 주소를 메뉴에 표시하지 않았다. 하위 도메인이 미정이기 때문이다.
- iPhone에서의 버튼 위치는 플랫폼 제공 순서가 미정이라 시안에 넣지 않았다.

## 남은 결정 사항

사용자가 정할 내용이다. 디자인은 결정에 맞춰 수정한다.

1. 공개 항목: 후보(프로젝트 정보, 완료한 할 일, 집중 시간, 티켓 메모)의 채택, 순서, 각 초기값, 일괄 설정 여부.
2. 공유 프로필 섹션의 최종 이름과 집중 로그 탭 안의 위치(소개 아래 또는 영상 편지함 아래).
3. 표시 이름과 사진: 이름과 사진을 바꾸는 위치(시안은 공유 프로필 카드의 `표시 이름` 행).
4. 잔디 집계 기준(완료 포모도로 수 또는 집중 시간), 표시 기간, 하루를 나누는 시각, 0.5포모도로와 중단 기록의 반영.
5. 활동 기록 갱신 방식: 자동 반영 또는 다시 게시.
6. 공개 중지와 재공개의 위치와 동작.
7. 배경 영상: 상단 띠 배치와 정지 버튼 제안의 채택 여부, 그라데이션 해시 입력(공개 프로필 ID 제안)과 링크를 다시 만들 때 색을 유지할지.
8. 플랫폼 제공 순서와 iPhone의 `공유하기` 위치.
9. 공유 링크 하위 도메인과 주소 형식.
10. 문구: `아직 문구가 없는 자리`의 항목.

## 구현과 배포

2026-11-08에 배포 순서 1~4를 모두 마쳤다. 공유 기능은 앱 0.7.0에 들어갔다.

### 구성

| 부분 | 파일 |
| --- | --- |
| 서버 테이블과 RPC, 저장소 | `supabase/migrations/202611080001_public_profiles.sql` |
| 공개 데이터 생성과 화면 렌더링(앱 미리보기와 Worker 공용) | `src/lib/public-profile.mjs`, `src/styles/public-profile.css` |
| 앱 메인 프로세스(사진 처리, 업로드, 링크 복사) | `electron/public-profile.mjs` |
| 앱 화면 | `src/components/Share*.svelte`, `src/lib/share-profile.ts`, `src/lib/share-copy.ts` |
| 공개 페이지 Worker | `workers/profile/`, `scripts/build-profile-worker.mjs` |
| 계정 삭제 시 공개 프로필과 `profiles` 저장소 정리 | `supabase/functions/delete-account/index.ts` |

- 공개 범위는 동기화 설정이 아니라 서버의 `public_profiles` 행에 저장한다. 기본값은 모두 꺼짐이다.
- 사진은 가운데를 정사각형으로 잘라 400px JPEG로 다시 저장한다. 위치 정보 같은 메타데이터는 남지 않는다.
- 공개를 중지하면 공개 데이터와 주간 영상을 지운다. 표시 이름, 사진, 공개 범위, 링크 ID는 남긴다.

### 배포 순서

1. Supabase에 `202611080001_public_profiles.sql` 마이그레이션을 적용한다.
2. `delete-account` Edge Function을 다시 배포한다.
3. `npm run profile:deploy -- --var SUPABASE_URL:<프로젝트 URL> --var SUPABASE_PUBLISHABLE_KEY:<공개 키>`로 Worker를 배포한다. `me.to3mato.com` 사용자 지정 도메인이 연결된다.
4. 공유 기능이 들어간 앱 버전을 릴리스한다.

1~3을 앱 릴리스보다 먼저 한다. 순서가 바뀌면 앱의 공유 저장이 실패한다.
