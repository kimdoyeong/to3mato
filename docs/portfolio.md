# To3mato 포트폴리오 정리

작성일: 2026-10-20
용도: 포트폴리오·이력서·면접 설명에 쓸 재료. 제품 문구가 아니므로 앱이나 웹사이트에 그대로 넣지 않는다.

## 한 줄 요약

할 일·캘린더·포모도로 타이머를 하나의 단위(포모도로)로 묶은 macOS 데스크톱 앱. 설계부터 서명·공증·자동 업데이트·CI/CD 배포까지 혼자 완성했고, 실제 배포 중이다.

- 앱 사이트: https://to3mato.com
- 현재 배포 버전: 0.3.3 (Apple Silicon, Developer ID 서명·Apple 공증)
- 스택: Electron 44 · Svelte 5 · Vite 8 · TypeScript · node:sqlite · Playwright · GitHub Actions · Cloudflare R2/Pages

## 뭐가 다른가 (차별점 5가지)

### 1. 타이머 앱이 아니라 "포모도로를 계획 단위로 쓰는" 앱

일반 포모도로 앱은 타이머이고, 일반 투두 앱은 목록이다. To3mato는 계획·배치·실행·회고를 전부 같은 단위로 다룬다.

| 단계 | 일반 앱 | To3mato |
| --- | --- | --- |
| 계획 | 분 단위 시간 추정 | 할 일마다 예상 포모도로 수 |
| 배치 | 시작 시각 고정 | 날짜와 순서만 정함. 시작이 늦어도 계획이 깨지지 않음 |
| 실행 | 타이머 따로 | 오늘 할 일 목록의 재생 버튼에서 바로 시작 |
| 회고 | 완료 체크 | 예상 vs 실제 집중량을 구분해 보존 |

설계상 중요한 결정 두 가지.

- 예상량을 다 써도 자동 완료하지 않는다. 집중량과 완료 여부를 분리한다.
- 작업 전환 시 중단된 집중량을 0 / 0.5 / 1포모도로로 반올림해 기록하고, 실제 초 단위 시간도 함께 저장한다. 다음 계획의 기준이 되는 데이터가 남는다.

근거: `docs/product-plan.md`, `src/lib/domain.mjs`의 `settleTimer`.

### 2. 3초 집중 클립과 월요일 영상 편지

집중 타이머가 끝나면 3초 영상을 찍을지 묻고, 매주 월요일 9시에 지난주 클립을 한 편의 영상으로 자동 합쳐 전달한다.

- 카메라는 사용자가 수락한 경우에만 켠다. 마이크는 쓰지 않는다.
- 합성은 기기 안에서 한다. 서버 업로드 없음.
- 앱을 꺼두어 놓친 주는 다음 실행에서 만든다. 같은 주는 중복 배달하지 않는다.
- 테스트는 가상 카메라로 촬영·권한 거부·취소·월요일 9시 경계·중복 배달 방지까지 검증한다.

근거: `src/components/CaptureMoment.svelte`, `src/lib/video.ts`, `src/lib/deliveries.ts`, `tests/focus-log.spec.ts`.

### 3. 데스크톱 앱의 기본기를 전부 갖춤

개인 프로젝트에서 보통 생략하는 부분을 생략하지 않았다.

| 영역 | 구현 |
| --- | --- |
| 보안 | 렌더러 `sandbox` + `contextIsolation`, `nodeIntegration` 비활성, IPC 발신자 검사, CSP `connect-src 'self'` |
| 저장 | Electron 내장 `node:sqlite` 사용. 네이티브 npm 모듈 없음. WAL + `synchronous=FULL`. 변경된 행만 쓰고 여러 작업은 한 트랜잭션 |
| 이전 | 기존 JSON 저장소를 첫 실행에 자동 이전. `PRAGMA user_version`으로 완료 기록. 손상 파일은 덮어쓰지 않고 중단 |
| 백업 | JSON 가져오기 전 DB 자동 백업. JSON 내보내기·가져오기 |
| 타이머 | 메인 프로세스가 단일 상태를 소유. 트레이·알림·창이 같은 상태를 공유. 절전·종료 시 자동 일시정지 |
| 트레이 | 메뉴 막대에 남은 시간 표시. 시작·일시정지·재개를 앱 없이 조작 |
| 알림 | macOS 네이티브 알림. 창이 뒤에 있어도 메인 프로세스에서 발송 |
| 오프라인 | 폰트·이미지 번들. 네트워크 없이 전부 동작 |
| 도메인 | `domain.mjs`는 Node·브라우저 의존성이 없는 순수 ESM. 단위 테스트와 서버 재사용 가능 |

근거: `electron/main.mjs`, `electron/storage.mjs`, `electron/tray.mjs`, `src/lib/domain.mjs`.

### 4. 서명·공증·자동 업데이트·CI/CD까지 실제로 돌아감

"만들었다"가 아니라 "배포하고 업데이트한다"까지 한 프로젝트다.

- `release/<버전>` 브랜치 푸시 → 검증 → macOS 러너 UI 테스트 → 임시 키체인에서 Developer ID 서명 + Apple 공증 → R2 업로드 → 웹사이트 재생성·배포 → 공개 페이지 검증. 네 단계가 GitHub Actions 한 워크플로다.
- 안전장치: 브랜치명과 package.json 버전 일치 검사, 원격 피드보다 낮은 버전 배포 거부, 업로드 직전 브랜치 끝 커밋 재확인, 공개 파일 해시 검증 후 `latest-mac.yml`을 마지막에 게시, 동시 실행 제한.
- 자동 업데이트: `electron-updater`로 서명 검증 후 설치 준비. 집중 타이머가 실행 중이면 재시작하지 않는다.
- 서명·공증된 두 버전 사이에서 실제 교체·재실행·데이터 보존을 확인하는 통합 테스트를 작성했다. 서버 503 재시도, 변조 ZIP 체크섬 거부까지 포함한다.
- 자격 증명은 전부 GitHub Secrets. 로컬 키체인을 추출하지 않는 등록 스크립트를 따로 두었다.

근거: `.github/workflows/release.yml`, `docs/release-ci-cd.md`, `docs/auto-update-design.md`, `tests/signed-update.spec.ts`, `scripts/upload-release.mjs`.

### 5. AI 에이전트와 함께 만들되 통제 장치를 설계함

이 프로젝트는 AI 코딩 에이전트를 적극적으로 썼다. 차별점은 "썼다"가 아니라 "에이전트가 반복해서 틀리는 지점을 규칙으로 고정했다"는 것이다.

- `AGENTS.md`에 카피 규칙을 명문화했다. 에이전트가 감성 문구·장식 라벨·메타 줄을 만드는 문제가 반복되자, 실제 삭제된 문구와 사용자 수정 전후 표를 남겨 같은 유형을 막았다.
- 설계 문서마다 "승인 필요 문구"와 "구현 전 확인" 항목을 두고 에이전트가 임의로 결정하지 못하게 했다.
- 릴리스 규칙에 "검증만 했으면 배포 완료라고 쓰지 않는다", "이미 배포한 파일을 덮어쓰지 않는다"를 적었다. 완료 보고의 정확성을 규칙으로 요구했다.
- 검증 결과를 파일로 남긴다. `release/distribution/deployment-verification.json`, `production-smoke.json` 등.

근거: `AGENTS.md`, `docs/sync-design.md`의 승인 항목, `docs/release-ci-cd.md` 완료 보고 절.

## 기술 결정과 이유

| 결정 | 대안 | 이유 |
| --- | --- | --- |
| `node:sqlite` | better-sqlite3, JSON 파일 | 네이티브 모듈 빌드·서명 문제 없음. 트랜잭션과 부분 저장 가능 |
| 타이머를 메인 프로세스에 | 렌더러 setInterval | 창 숨김·절전에 영향받지 않음. 트레이·알림과 단일 상태 |
| 순수 ESM 도메인 모듈 | 컴포넌트 안 로직 | 브라우저 미리보기·Electron·테스트·향후 서버에서 같은 코드 |
| R2 + 정적 Pages | GitHub Releases | 자체 도메인, 캐시 정책 제어, 사이트와 피드를 같은 배포에서 검증 |
| 웹사이트 HTML/CSS만 | 프레임워크 | 런타임 JS·CDN 없음. 스크립트로 실제 앱 화면을 촬영해 삽입 |
| Supabase (동기화 설계) | Cloudflare Workers 직접 운영 | 인증·RLS·DB를 직접 만들지 않음. 설계 단계에서 비교 후 변경 |

## 솔직한 한계

- 검증 대상은 macOS Apple Silicon뿐이다. Windows·Linux 패키징 설정은 있지만 실행하지 않았다.
- 계정·동기화는 설계만 있고 구현 전이다. HLC 타임스탬프, tombstone, 변경 로그 기반 설계를 `docs/sync-design.md`에 정리했다.
- 여러 날짜로 분량을 나누는 계획과 예상량 변경 이력은 미구현이다.
- git 이력은 0.3.0 시점부터 시작한다. 그 이전 버전의 작업 이력은 문서로만 남아 있다.

## 그대로 쓸 수 있는 문구

### 이력서 3줄

- 할 일·캘린더·포모도로를 하나의 단위로 통합한 macOS 앱을 Electron·Svelte·SQLite로 설계·구현·배포 (0.3.3 배포 중)
- Developer ID 서명·Apple 공증·electron-updater 자동 업데이트·R2/Pages 배포를 GitHub Actions 단일 워크플로로 자동화. 서명 앱 간 실제 교체를 검증하는 통합 테스트 작성
- AI 코딩 에이전트 협업 규칙(카피·릴리스·완료 보고)을 문서화해 반복 오류를 제거

### 소개 3문장

To3mato는 "몇 분 걸릴까" 대신 "몇 포모도로 할까"로 하루를 계획하고 그대로 실행·기록하는 macOS 앱입니다. 타이머·트레이·알림·SQLite 저장·자동 업데이트까지 데스크톱 앱에 필요한 기반을 모두 직접 구현했고, 서명·공증·배포는 GitHub Actions로 자동화해 실제 배포 중입니다. 집중이 끝난 순간을 3초 영상으로 남겨 매주 월요일 한 편으로 합쳐주는 기능이 있습니다.

### 면접에서 꺼낼 이야기

1. 왜 예상 포모도로를 다 써도 자동 완료하지 않는가. (집중량과 완료의 분리)
2. 작업 전환 시 중단된 시간을 어떻게 기록하는가. (0/0.5/1 반올림 + 실제 초 보존)
3. 자동 업데이트에서 집중 타이머가 실행 중일 때 어떻게 하는가. (재시작 금지, 종료 시 교체)
4. `latest-mac.yml`을 왜 마지막에 올리는가. (파일 해시 검증 전 피드 노출 방지)
5. 에이전트가 카피를 망가뜨리는 문제를 어떻게 해결했는가. (삭제 문구 사례집 + 승인 절차)

## 포트폴리오에 넣을 때 확인할 것

- `website/dist/assets/app-focus-log.png`에는 `LITTLE MOMENTS, EVERY DAY`, `집중이 모여, 나의 한 주`, `배달할게요` 같은 문구가 있다. `AGENTS.md`의 금지 유형(영문 라벨, 쉼표 리듬, 감성 화법)에 해당한다. 포트폴리오에 이 화면을 쓰기 전에 앱 문구를 정리하고 다시 촬영하는 편이 낫다.
- `app-today.png`는 규칙에 맞는 화면이다. 대표 이미지로 쓰기 적합하다.
- 다운로드 페이지 템플릿의 버전 표기(`v0.3.0`)는 CI가 배포 시점에 갱신한다. 저장소 파일을 그대로 캡처하면 현재 공개 버전과 다르다.
